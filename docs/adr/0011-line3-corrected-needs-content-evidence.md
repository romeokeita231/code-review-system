# 0011 line 3 的已修好需要内容级判据

- Status: Accepted
- Date: 2026-11-27
- Source: #50

## Context

line 3 现在判定「已修好」只用一条证据：warn 之后的后续写里，没有再次出现同类 CWE。`scripts/acceptance.ts` 的判定只读带非空 CWE 的命中，未归类命中不参与。

所以「已修好」的真实含义是「没有检出同类」，不是「缺陷行已不存在」。当前判据无法区分「修好了」与「改坏了但没被检出」。ds-2 的 20 个有 GT 类的样本里，只有 CWE-798 能被证伪（semgrep 在同一文件同一行仍报）；其余 9 个「已修好」都只是没有同类命中。

数据是齐的：GT 标签带文件路径与起止行，样本里存着植入缺陷后的完整文件内容，运行目录的 scratch 下留着 B4/B4g 各自的最终文件，还有一份路径映射。当前数据集每个样本最多一个 GT 标签。

## Decision

- 「已修好」收紧为三个条件同时成立：warn 之后有写、后续写不再报同类、GT 标注的缺陷内容已不在最终文件中。
- 内容比对口径：取 GT 标签覆盖的整段文本，逐行去首尾空白、连续空白折叠为单个空格，在最终文件全文里做子串搜索；不做行号对齐。整段文本为空时该标签不参与比对。
- 新增两态：**未移除**（有写、没再报同类，但内容仍在）与**未测到**（最终文件缺失、读不到，或该 run 没有快照）。两者都计入 line 3 失败，分母不变。
- 状态优先级：未修（warn 后无写）→ 复发（又报同类）→ 未测到 → 未移除 → 已修好。先复用已有证据，内容判据只在检测没报警时兜底。
- 最终文件内容由汇总阶段抓成快照存进运行目录，报告只读快照；报告要同时写出「比对了几个 pair」与「缺几个」，缺省写 `na`，不写 0。
- 旧 run 没有快照时沿用仅检测判据，明细标示「仅检测」；已发布的 9/1/10 不回溯重写。
- 判据在 `artifacts/preregistration.json` 追加 revision 后生效，不设运行时开关。
- 已知假阴性并接受：agent 只重排格式、语义未变时会被判为已修好。它仍比「没检出」更接近内容事实。

## Consequences

- line 3 会更严格：内容仍在或无法比对时不再通过，可能因此不通过。
- 运行目录多一份最终文件快照；汇总与报告各多一个输入，报告明细必须显示内容判据的覆盖情况。
- 没有快照的旧 run 读法与之前一致，不会被新判据伪装成更强证据。
- 格式重排导致的假阴性是登记过的限制，不是待修复缺陷。
